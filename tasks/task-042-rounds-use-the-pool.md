# Task 042 — Rounds use the pool, the report says so, `/questions` goes away

PRD §03 (knowledge tiers), §04 (provenance), §09 (rounds), §11 (report).
Depends on **task 039** (pool tables and repository). Read `CLAUDE.md` first —
**rule 7 applies: no live rounds, no Gemini calls.** Tests with the AI mocked, and CI.

Branch from `origin/develop`, or from 039's branch if it is not merged when you start; say
which in your report.

## Why

The pool is useless until a round reaches for it, and dangerous until the report says what
it is. Both halves ship together — a pool question in a round without its label is a model's
guess presented as knowledge of a real employer.

## Selection order

A round asks, in this order:

1. **The sourced bank** (task 038, `BankRoundPlanner`) — a real report that a real employer
   asked this. Unchanged; it keeps first claim.
2. **The AI pool** (task 039) — when the bank has nothing for this company and round type.
   Match on (company, round type, role family, level); fall back within the company to the
   nearest level, then to the archetype-level rows, before giving up.
3. **Live AI**, as today — when neither has anything. This path stays; it is the floor, not
   the default.

**Never repeat a question for a candidate.** `session_turns.bank_question_id` already does
this for the bank (`20260914010000_bank_rounds.sql`, and `askedBankQuestions` in
`SessionRepository`). Add `pool_question_id` the same way — additive migration
`20260915020000_session_turn_pool_question.sql`, FK to `pool_questions` with
`on delete set null`, and the same partial index on `(user_id, pool_question_id)`. Exclusion
works across sessions, not just within a round, exactly as the bank's does. Reuse
`BankQuestionSelection`'s shape rather than writing a second selector with different
behaviour.

## The label

A pool question is `MODEL_KNOWLEDGE` in `ProvenanceTier`, and **the tier is decided by the
engine, never by the model** (`QuestionProvenance.kt` already says so — keep it true).

What the report shows for a pool question, and nothing else:

> Generated by our AI interviewer from general knowledge. Not a verified report of a
> question <Company> asked.

For a question whose `association` is `employer_kind` — a company the model does not know
well — the wording is about **the kind of employer, not the company**: name the archetype,
not the employer. Task 039 stored which it is; read it, do not re-derive it.

Sourced questions are untouched: they keep their citations, corroboration and recency.
Attribution is the basis on which those posts are used at all.

A plain unit test asserting the exact sentence for each of the two cases, and that a sourced
question never renders either of them.

## Hide `/questions`

The browsable question bank goes behind a config flag, **off by default**. Not deleted —
the sourced bank stays in the backend and rounds keep using it.

- One property, `interviewos.question-bank.browsable` (default `false`), and one env var,
  surfaced to the web app the way other flags already are. With it off:
  - `apps/web/src/app/questions/page.tsx` and `apps/web/src/app/questions/[slug]/page.tsx`
    return a 404 (`notFound()`), not a redirect and not an empty page.
  - The "Questions" entry disappears from `rail-nav.tsx`.
  - The "see them" link in `loop-brief-step.tsx` disappears.
  - `GET /api/v1/question-bank/companies` and `GET /api/v1/question-bank` return 404. The
    **list** endpoints only: whatever a round needs from the bank keeps working, and the
    tests must prove a round still gets its sourced questions with the flag off.
- **No pool endpoint is added, ever.** The pool is not listed to a client under any flag.
  039's admin export is how the owner sees it.
- Tests both ways: flag off (404s, no nav entry, no link, rounds still work) and flag on
  (everything as it is today, so the existing tests keep passing).

## Testing

- Unit-test the selection order: bank present → bank; bank empty, pool present → pool; both
  empty → live AI. And that a question already asked by this candidate is not offered again,
  from either store.
- Integration test for a round that draws from the pool: the turn records
  `pool_question_id`, the provenance tier is `model_knowledge`, and the report carries the
  label.
- AI mocked at the boundary. No live third-party call.
